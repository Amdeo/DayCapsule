## 应用侧结构

当前移动端应用基于 Expo / React Native，使用 Expo Router 作为入口，围绕本地数据、媒体能力、认证与云同步组织实现。

应用侧可以按职责理解为四层：

- 路由与页面入口
- 业务服务
- 状态管理
- 本地数据与持久化

从当前实现看，应用不是单一页面集合，而是由“内容记录 + 媒体处理 + 账户状态 + 同步状态”共同组成的完整客户端。首页内容、设置、认证、上传、同步和备份都已经纳入同一套应用结构中。

## 主要能力

当前应用的核心能力可以概括为四条主线：

- 内容记录：支持文字、照片、语音三类记录，并提供首页浏览、搜索、筛选与编辑相关能力
- 媒体处理：支持照片与语音的采集、准备、上传、恢复与基础校验
- 账户与同步：支持登录、认证恢复、云端模式、本地与云端数据同步
- 数据保全：同时提供本地持久化、本地备份和云端恢复相关能力

核心运行链路可以这样理解：

应用启动后会先完成本地初始化与状态恢复，再进入内容读取与展示；当用户创建或修改内容时，应用会根据当前模式决定是仅本地落盘，还是继续进入上传与同步链路；当启用后端能力时，认证、同步和媒体恢复会接入这条主流程。

整体上，当前实现已经覆盖了“本地优先使用”和“接入后端后的同步使用”这两种实际运行方式。

## 后端侧

当前后端是仓库内自带的一套轻量服务，用来承接认证、数据同步和媒体访问相关能力。

从现有部署文档与编排文件看，后端侧当前由以下部分组成：

- Go + Gin 服务
- SQLite 单文件数据库
- 本地磁盘媒体存储
- Docker Compose 编排
- Nginx 反向代理入口

对应到系统链路，可以把它理解为：移动端应用通过配置的后端地址访问仓库内 API 服务；后端服务再基于本地数据库和本地文件存储完成数据与媒体处理。

后端部署相关事实与文件入口位于 `docs/BACKEND_DEPLOYMENT.md`。
