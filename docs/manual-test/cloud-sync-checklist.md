# 云同步手测 Checklist

## 文档导航

- 快速执行：`docs/manual-test/cloud-sync-checklist.md`
- 正式用例表：`docs/manual-test/cloud-sync-test-cases.md`
- 冲突专项：`docs/manual-test/cloud-sync-conflict-test-cases.md`
- 媒体专项：`docs/manual-test/cloud-sync-media-test-cases.md`
- 推荐执行顺序：`docs/manual-test/cloud-sync-recommended-order.md`

你可以直接按这个顺序测，边测边打勾。
每条都尽量记录：

- 是否通过
- 卡在哪一步
- A/B 两端最终表现
- 同步状态页表现
- 是否有截图

---

## 0. 测试前检查

- [ ] 设备 A 可正常使用
- [ ] 设备 B 可正常使用
- [ ] 两台设备都能登录同一账号
- [ ] 两台设备都能访问后端
- [ ] 两台设备都能打开设置页和同步状态页
- [ ] 已准备一个“云端有数据”的账号
- [ ] 已准备一个“云端为空”的账号，或可确认云端为空
- [ ] 已准备截图/录像方式，方便记录异常

---

## 1. 首次同步：本地为空，从云恢复

**目标**
验证：本地空、云端有数据时，选择“从云恢复”能否成功。

**前置条件**

- [ ] 设备 A 本地为空
- [ ] 云端已有文本、照片、语音数据
- [ ] 设备 B 已确认这些云端数据确实存在

**步骤**

- [ ] 设备 A 打开 App
- [ ] 登录“云端有数据”的测试账号
- [ ] 确认设备 A 首页为空
- [ ] 进入设置页
- [ ] 打开云同步
- [ ] 出现首次同步选择时，选择“从云端恢复”
- [ ] 等待恢复完成
- [ ] 返回首页
- [ ] 检查文本记录是否出现
- [ ] 检查照片记录是否出现
- [ ] 检查语音记录是否出现
- [ ] 打开照片详情，检查图片是否正常
- [ ] 打开语音详情，检查是否可播放
- [ ] 打开同步状态页
- [ ] 检查最近同步时间是否更新
- [ ] 检查是否仍有明显错误提示

**通过标准**

- [ ] 云端记录完整恢复到 A
- [ ] 没有重复记录
- [ ] 照片可显示
- [ ] 语音可播放
- [ ] 同步状态页没有长期异常

**异常记录**

- [ ] 记录恢复不全
- [ ] 照片空白
- [ ] 语音不可播放
- [ ] 恢复后列表又被清空
- [ ] 同步状态一直卡住

---

## 2. 首次同步：本地有数据，备份到云端

**目标**
验证：本地有数据、云端为空时，选择“备份本地到云端”能否成功。

**前置条件**

- [ ] 设备 A 使用“云端为空”的账号
- [ ] 设备 B 登录同一账号时看不到历史数据
- [ ] 设备 A 本地已准备：
- [ ] 2 条文本
- [ ] 1 条照片
- [ ] 1 条语音

**建议测试数据**

- `INIT-LOCAL-TEXT-1`
- `INIT-LOCAL-TEXT-2`
- `INIT-LOCAL-PHOTO-1`
- `INIT-LOCAL-VOICE-1`

**步骤**

- [ ] 设备 A 登录账号
- [ ] 确认本地可看到以上 4 条记录
- [ ] 打开设置页
- [ ] 启用云同步
- [ ] 首次同步选择“将本地数据备份到云端”
- [ ] 等待同步完成
- [ ] 打开同步状态页
- [ ] 检查最近同步时间
- [ ] 检查待同步数量是否下降
- [ ] 检查待上传/上传中数量是否最终恢复正常
- [ ] 在设备 B 登录同一账号
- [ ] 打开首页并刷新
- [ ] 检查两条文本是否出现
- [ ] 检查照片记录是否出现并可查看
- [ ] 检查语音记录是否出现并可播放

**通过标准**

- [ ] A 本地数据未丢失
- [ ] B 最终能看到全部记录
- [ ] 照片和语音可用
- [ ] 状态最终收敛正常

**异常记录**

- [ ] 文本到了，媒体没到
- [ ] 某条记录永远卡住
- [ ] 出现重复记录
- [ ] 本地备份后反被云端覆盖

---

## 3. 日常同步：新增文本记录

**目标**
验证：新建文本能从 A 同步到 B。

**测试数据**

- `TEXT-CREATE-001`

**步骤**

- [ ] 在设备 A 首页新建文本
- [ ] 输入 `TEXT-CREATE-001`
- [ ] 保存
- [ ] 确认 A 首页立即看到这条记录
- [ ] 打开 A 的同步状态页
- [ ] 等待几秒，必要时手动点“立即同步”
- [ ] 检查最近同步时间是否更新
- [ ] 在设备 B 打开首页
- [ ] 下拉刷新
- [ ] 查找 `TEXT-CREATE-001`
- [ ] 打开详情确认内容

**通过标准**

- [ ] A 创建后立即可见
- [ ] B 最终可见
- [ ] 内容一致
- [ ] 无重复记录

**异常记录**

- [ ] B 端看不到
- [ ] 同步后又消失
- [ ] 出现 2 条相同记录
- [ ] 同步状态显示成功但 B 没有

---

## 4. 日常同步：编辑文本记录

**目标**
验证：编辑文本后更新能同步到 B。

**测试数据**

- 原记录：`TEXT-CREATE-001`
- 修改后：`TEXT-EDIT-001-AFTER`

**步骤**

- [ ] 在 A 打开 `TEXT-CREATE-001`
- [ ] 点击编辑
- [ ] 改成 `TEXT-EDIT-001-AFTER`
- [ ] 保存
- [ ] 确认 A 首页或详情显示新内容
- [ ] 打开 A 同步状态页
- [ ] 等待同步完成
- [ ] 在 B 打开相同记录
- [ ] 刷新
- [ ] 检查是否显示 `TEXT-EDIT-001-AFTER`

**通过标准**

- [ ] A 立即看到新内容
- [ ] B 最终也看到新内容
- [ ] 没有新增副本
- [ ] 没有回退旧内容

**异常记录**

- [ ] B 仍是旧内容
- [ ] 编辑后被覆盖回去
- [ ] 生成第二条记录
- [ ] 显示同步成功但内容未更新

---

## 5. 日常同步：删除已同步文本记录

**目标**
验证：删除后会同步到 B。

**测试对象**

- `TEXT-EDIT-001-AFTER`

**步骤**

- [ ] 在 A 找到这条记录
- [ ] 进入详情
- [ ] 点击删除
- [ ] 确认删除
- [ ] 确认 A 首页中该记录已消失
- [ ] 打开 A 同步状态页
- [ ] 等待同步完成
- [ ] 在 B 打开首页
- [ ] 执行刷新
- [ ] 确认该记录已消失

**通过标准**

- [ ] A 删除后立即消失
- [ ] B 最终也消失
- [ ] 没有“删了又回来”

**异常记录**

- [ ] B 端残留
- [ ] 删除后又回来了
- [ ] 删除过程中出现重复
- [ ] 状态页长期异常

---

## 6. 照片同步：新增单张照片记录

**目标**
验证：照片记录可上传到云端，并在 B 正常显示。

**测试数据**

- 标题或说明：`PHOTO-ONE-001`

**步骤**

- [ ] 在 A 创建照片记录
- [ ] 拍摄或选择 1 张图片
- [ ] 输入 `PHOTO-ONE-001`
- [ ] 保存
- [ ] 确认 A 首页立即出现这条照片记录
- [ ] 打开 A 同步状态页
- [ ] 观察是否出现待上传/上传中
- [ ] 等待状态恢复正常
- [ ] 在 B 打开首页
- [ ] 刷新
- [ ] 找到 `PHOTO-ONE-001`
- [ ] 打开详情
- [ ] 检查缩略图
- [ ] 检查大图/原图是否可看

**通过标准**

- [ ] A 本地立即可见
- [ ] B 最终可见
- [ ] B 图片可显示
- [ ] 无长期 pending_upload / uploading

**异常记录**

- [ ] 只有文字，没有图片
- [ ] 缩略图有，原图打不开
- [ ] B 端图片损坏
- [ ] A 端状态一直卡上传中

---

## 7. 语音同步：新增语音记录并跨端播放

**目标**
验证：语音文件能同步并在 B 播放。

**测试数据**

- 口播内容：`VOICE-ONE-001`

**步骤**

- [ ] 在 A 创建语音记录
- [ ] 录制 5 到 10 秒
- [ ] 口播 `VOICE-ONE-001`
- [ ] 停止并保存
- [ ] 返回首页确认该语音记录可见
- [ ] 在 A 先播放一次，确认本地正常
- [ ] 打开 A 同步状态页
- [ ] 等待同步完成
- [ ] 在 B 打开首页
- [ ] 刷新
- [ ] 找到该语音记录
- [ ] 打开详情
- [ ] 点击播放

**通过标准**

- [ ] A 本地可播放
- [ ] B 最终可见
- [ ] B 可以播放
- [ ] 不只是卡片到了，音频也有效

**异常记录**

- [ ] B 有卡片但不能播放
- [ ] 时长异常
- [ ] 同步完成但音频资源无效
- [ ] 状态页长时间异常

---

## 8. 多端冲突：A/B 同时编辑同一条文本

**目标**
验证：冲突时系统能稳定收敛，不会静默丢失修改。

**前置条件**

- [ ] A、B 都有同一条记录
- [ ] 建议先创建一个专用记录：`CONFLICT-BASE-001`
- [ ] A、B 确保都已同步到同一版本

**步骤**

- [ ] 在 A 打开 `CONFLICT-BASE-001`
- [ ] 在 B 也打开 `CONFLICT-BASE-001`
- [ ] A 端点击编辑
- [ ] 改成 `CONFLICT-A-VERSION`
- [ ] 保存
- [ ] 不等待 B 刷新
- [ ] 直接在 B 点击编辑
- [ ] 改成 `CONFLICT-B-VERSION`
- [ ] 保存
- [ ] 等待 A 同步
- [ ] 等待 B 同步
- [ ] 查看 A 最终内容
- [ ] 查看 B 最终内容
- [ ] 查看首页是否有冲突副本
- [ ] 查看同步状态页是否有冲突相关表现

**通过标准**

- [ ] A、B 最终能收敛
- [ ] 不会长期一边一个版本
- [ ] 如果产品设计有冲突副本，应能看到
- [ ] 不会两边都丢数据
- [ ] 不会无缘无故生成很多重复项

**异常记录**

- [ ] A/B 长期不一致
- [ ] 一边变空
- [ ] 某个版本被静默吞掉
- [ ] 冲突后出现多条重复

---

## 9. 失败恢复：断网后恢复同步

**目标**
验证：网络失败后，本地数据不丢，恢复网络后能继续同步。

**测试数据**

- `OFFLINE-RECOVER-001`

**步骤**

- [ ] 在 A 断网
- [ ] 创建一条文本记录 `OFFLINE-RECOVER-001`
- [ ] 保存
- [ ] 确认 A 首页仍可见
- [ ] 打开同步状态页
- [ ] 检查是否出现失败/待同步/错误提示
- [ ] 恢复网络
- [ ] 回到 App
- [ ] 等待自动同步，或手动点“立即同步”
- [ ] 检查最近同步时间是否更新
- [ ] 检查错误状态是否消失
- [ ] 在 B 首页刷新
- [ ] 查找 `OFFLINE-RECOVER-001`

**通过标准**

- [ ] 离线创建时本地不丢
- [ ] 恢复网络后能同步到 B
- [ ] 失败状态最终可恢复
- [ ] 不需要重建记录

**异常记录**

- [ ] 网络恢复后仍永久失败
- [ ] 必须重启 App 才能恢复
- [ ] B 端收不到
- [ ] 错误状态一直残留

---

## 10. 恢复能力：同步未完成时杀掉 App，再重启

**目标**
验证：未完成的媒体上传/同步任务可在重启后恢复。

**建议测试数据**

- 照片：`RESTART-RECOVER-PHOTO-001`
- 或语音：`RESTART-RECOVER-VOICE-001`

**步骤**

- [ ] 在 A 创建一条照片或语音记录
- [ ] 保存后立刻打开同步状态页
- [ ] 在任务明显未完成时，强制关闭 App
- [ ] 等 5 到 10 秒
- [ ] 重新打开 App
- [ ] 登录同一账号
- [ ] 打开首页，确认这条记录还在
- [ ] 打开同步状态页
- [ ] 观察是否自动恢复上传/同步
- [ ] 等待一段时间
- [ ] 在 B 首页刷新
- [ ] 如果是照片，检查图片是否可看
- [ ] 如果是语音，检查是否可播放

**通过标准**

- [ ] 重启后本地记录不丢
- [ ] 未完成任务能继续推进
- [ ] B 最终能拿到完整记录
- [ ] 照片/语音内容可用
- [ ] 不会长期卡在 pending_upload / uploading

**异常记录**

- [ ] 重启后记录丢失
- [ ] 重启后状态卡死
- [ ] 只有元数据同步了，媒体没同步
- [ ] 必须手动做额外操作才恢复
