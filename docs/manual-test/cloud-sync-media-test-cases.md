# 云同步媒体专项手测

## 文档导航

- 快速执行：`docs/manual-test/cloud-sync-checklist.md`
- 正式用例表：`docs/manual-test/cloud-sync-test-cases.md`
- 冲突专项：`docs/manual-test/cloud-sync-conflict-test-cases.md`
- 媒体专项：`docs/manual-test/cloud-sync-media-test-cases.md`
- 推荐执行顺序：`docs/manual-test/cloud-sync-recommended-order.md`

本文档专门覆盖照片与语音的上传、跨端展示、失败恢复、重启恢复，以及媒体完整性异常场景。

---

## 测试目标

- 验证照片记录的上传、下载和跨端查看
- 验证语音记录的上传、下载和跨端播放
- 验证弱网、断网、重启场景下媒体任务是否可恢复
- 验证媒体同步异常时，状态页和页面表现是否可感知
- 验证媒体记录的元数据更新不会破坏媒体内容可用性

---

## 通用前置条件

- [ ] 设备 A、设备 B 登录同一账号
- [ ] 云同步已开启
- [ ] 两端网络正常
- [ ] 设备 A 有相机、相册、录音权限
- [ ] 可访问首页、详情页、设置页、同步状态页

---

## 场景 1：新增单张照片记录并跨端查看

**目标**
验证单张照片从本地创建到另一端显示的完整链路。

**步骤**

- [ ] A 新建照片记录
- [ ] 拍摄或选择 1 张图片
- [ ] 输入说明 `MEDIA-PHOTO-ONE-001`
- [ ] 保存
- [ ] 确认 A 首页立即出现该记录
- [ ] 打开 A 同步状态页，观察是否出现待上传/上传中
- [ ] 等待状态恢复正常
- [ ] B 刷新首页
- [ ] 打开该记录详情
- [ ] 检查缩略图和原图

**预期结果**

- [ ] A 本地立即可见
- [ ] B 最终可见
- [ ] B 可正常查看图片
- [ ] 不长期卡在 `pending_upload` / `uploading`

---

## 场景 2：新增多张照片记录

**目标**
验证一条多图记录中的所有图片都能同步并保持稳定顺序。

**步骤**

- [ ] A 新建照片记录
- [ ] 选择 3 张图片
- [ ] 输入说明 `MEDIA-PHOTO-MULTI-001`
- [ ] 保存并等待同步
- [ ] B 刷新首页并打开详情
- [ ] 逐张检查图片是否可见
- [ ] 检查图片顺序是否稳定

**预期结果**

- [ ] B 能看到全部图片
- [ ] 不只同步部分图片
- [ ] 不出现重复图或顺序明显错乱

---

## 场景 3：编辑带照片记录的文字或标签

**目标**
验证更新元数据不会破坏图片可用性。

**步骤**

- [ ] 准备一条已同步的照片记录
- [ ] A 编辑说明文字为 `MEDIA-PHOTO-EDIT-001`
- [ ] 或编辑标签
- [ ] 保存并等待同步
- [ ] B 刷新并打开该记录
- [ ] 检查新文字/标签
- [ ] 再检查图片是否仍可查看

**预期结果**

- [ ] 说明文字或标签更新成功
- [ ] 图片仍正常显示
- [ ] 不出现“文字同步成功但图片失效”

---

## 场景 4：弱网或断网下新增照片记录

**目标**
验证图片上传失败后的恢复能力。

**步骤**

- [ ] A 先断网或切到弱网
- [ ] A 新建照片记录并保存，说明 `MEDIA-PHOTO-OFFLINE-001`
- [ ] 确认本地记录仍在
- [ ] 查看同步状态页是否出现待上传、失败或错误提示
- [ ] 恢复网络
- [ ] 等待自动恢复或手动触发同步
- [ ] B 刷新查看结果

**预期结果**

- [ ] 本地记录不丢失
- [ ] 恢复网络后最终能同步到 B
- [ ] 图片在 B 可查看

---

## 场景 5：新增语音记录并跨端播放

**目标**
验证语音记录的上传、跨端同步和播放。

**步骤**

- [ ] A 新建语音记录
- [ ] 录制 5 到 10 秒，口播 `MEDIA-VOICE-ONE-001`
- [ ] 保存
- [ ] A 本地先播放一次
- [ ] 等待同步完成
- [ ] B 刷新首页
- [ ] 打开语音记录详情
- [ ] 点击播放

**预期结果**

- [ ] A 本地可播放
- [ ] B 最终可见并可播放
- [ ] 时长基本正确

---

## 场景 6：录制完成后立即切后台或退出

**目标**
验证语音上传队列在中断后可恢复。

**步骤**

- [ ] A 新建语音记录并录制保存
- [ ] 保存后立即切后台或退出页面
- [ ] 稍等后重新进入 App
- [ ] 打开同步状态页观察状态变化
- [ ] 等待同步完成
- [ ] B 刷新并尝试播放

**预期结果**

- [ ] A 本地语音不丢
- [ ] 恢复后任务能继续
- [ ] B 最终可播放

---

## 场景 7：断网下新增语音记录

**目标**
验证语音记录在网络失败后可恢复同步。

**步骤**

- [ ] A 断网
- [ ] A 新建语音记录，口播 `MEDIA-VOICE-OFFLINE-001`
- [ ] 保存并确认本地存在
- [ ] 查看状态页错误或待同步状态
- [ ] 恢复网络
- [ ] 手动或自动触发同步
- [ ] B 刷新并播放

**预期结果**

- [ ] 本地语音不丢失
- [ ] 恢复网络后最终同步到 B
- [ ] B 可播放

---

## 场景 8：同步未完成时杀掉 App，再重启

**目标**
验证媒体任务在重启后可以继续推进。

**步骤**

- [ ] A 新建一条照片或语音记录
- [ ] 保存后立刻打开同步状态页
- [ ] 在任务未完成时强制关闭 App
- [ ] 重新打开 App
- [ ] 确认记录仍在首页
- [ ] 观察状态页是否自动恢复
- [ ] B 刷新并验证媒体是否可用

**预期结果**

- [ ] 本地记录不丢
- [ ] 未完成任务恢复继续
- [ ] B 最终拿到完整可用媒体

---

## 场景 9：媒体异常时的用户可感知性

**目标**
验证媒体失败时，用户能从状态页或页面中感知异常，而不是静默失败。

**步骤**

- [ ] 制造一次媒体上传失败或下载失败场景
- [ ] 打开同步状态页
- [ ] 观察是否有失败数量、错误提示或待处理状态
- [ ] 回到首页和详情页，观察媒体卡片表现

**预期结果**

- [ ] 失败有可见状态
- [ ] 用户能感知媒体尚未成功同步
- [ ] 不出现“表面成功但媒体实际不可用且无任何提示”
