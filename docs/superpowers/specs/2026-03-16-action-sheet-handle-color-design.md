# 设计文档：将底部面板类型色条收进顶部 Handle

**日期：** 2026-03-16  
**状态：** 已批准  
**影响范围：** `EntryActionSheet`、对应测试

---

## 背景

当前底部操作面板顶部由两层视觉元素组成：

1. 最上方一条独立的类型色条
2. 色条下方一个灰色的小拖拽条（handle）

用户希望顶部更简洁，不要再保留独立的类型色条，而是把类型色信息收进小拖拽条本身。

---

## 已确认的设计决策

### 1. 保留顶部 handle

- 不移除顶部小拖拽条
- 顶部仍保留一个可视的 pill 形 handle，作为面板的拖拽提示

### 2. 去掉独立色条

- 删除当前位于面板顶部的独立类型色条
- 顶部不再出现额外一整条横向色块

### 3. 类型色承载方式

用户已在视觉预览中选择：

- **方案 A：整根 handle 直接使用类型色**

即：

- `text` → `#A491D3`
- `photo` → `#77C9D4`
- `voice` → `#F5A623`

不采用：

- 灰底 + 中间彩色点缀
- 灰到类型色渐变

---

## 方案对比

### 方案一：整根 handle 使用类型色（推荐，已选定）

将顶部 handle 直接设置为当前条目类型对应的颜色。

**优点**

- 最直接
- 视觉最干净
- 完整保留类型色信息，同时避免顶部出现两层装饰

**缺点**

- 类型色信息比“整条顶边染色”更克制

### 方案二：灰底 handle + 中间彩色点缀

handle 主体仍为灰色，中间再嵌入一小段类型色。

**优点**

- 更偏系统风格
- 视觉更保守

**缺点**

- 类型色信息偏弱
- 顶部会显得不够明确

### 方案三：灰到类型色渐变 handle

handle 使用从灰到类型色的渐变。

**优点**

- 更柔和
- 更有设计感

**缺点**

- 风格偏花
- 与当前面板的极简方向不完全一致

### 结论

采用**方案一**：去掉独立色条，直接让 handle 使用类型色。

---

## 视觉结构

### 调整前

- 顶部独立类型色条
- 灰色 handle
- 白色面板主体

### 调整后

- 删除独立类型色条
- 顶部只保留一个居中的彩色 handle
- 面板主体继续保持纯白

### Handle 规格

建议：

- `width: 40`
- `height: 6`
- `borderRadius: 999`
- 居中显示

颜色映射：

- `text` → `#A491D3`
- `photo` → `#77C9D4`
- `voice` → `#F5A623`

---

## 实现边界

### 本次修改包含

- 删除 `EntryActionSheet` 顶部独立色条
- 将 `handle` 的背景色改为按 `entryType` 映射
- 保持默认菜单态和删除确认态顶部结构一致

### 本次修改不包含

- 不改 `EntryCard` 的左滑触发逻辑
- 不改 `Timeline` 的互斥控制
- 不改底部面板的进入/退出时序
- 不改删除确认流程
- 不额外增加描边、阴影、渐变等新装饰

---

## 测试要点

1. 面板可见时顶部不再渲染独立类型色条。
2. 顶部 handle 存在且使用当前 `entryType` 对应颜色。
3. 删除确认视图顶部仍然沿用同一套彩色 handle。
4. 菜单态与确认态的其余功能不受影响。

---

## 实施提示

这是一次收敛的视觉微调，不应扩展成整体重做。

目标只有一个：

- **删掉顶部独立色条**
- **把类型色收进顶部 handle**

只要面板顶部从“双层”变成“单层”，这次设计目标就达成。
