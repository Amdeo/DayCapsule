# 双图卡片主辅拼贴设计

**日期**: 2026-03-25
**状态**: 已批准
**阶段**: 仅调整双图展示规则

## 目标

解决图片卡片在恰好 2 张图时“2 列等宽正方形”过于机械、对随机比例容错较差的问题。

本次设计的优先级是：

1. 在时间轴里保持整体稳定统一
2. 允许主辅不等大，提升双图观感
3. 优先保留用户选择顺序，但允许在明显更合适时交换主辅

---

## 问题

当前 `PhotoGrid` 对 2 张图的处理与 3 张图一致，采用等宽等高的并排格子：

- 规则简单，但对“横图 + 竖图”或比例差异很大的组合不友好
- 两张图都被强行裁成方块，裁切压力大
- 列表中看起来整齐，但缺少主次，且容易显得僵硬

这类实现适合纯网格浏览，不适合时间轴里的内容卡片。

---

## 设计决策

双图卡片统一改为 `固定高度的横向主辅拼贴`，不再使用 `2 列等宽正方形`。

核心规则：

- 外层容器高度固定，保证时间轴节奏稳定
- 主图位宽度约占 `64%`，辅图位宽度约占 `36%`
- 默认第一张为主图
- 当第二张与主图位的匹配度明显更高时，允许交换主辅
- 两张图均使用 `resizeMode="cover"`
- 展示顺序允许重排，但图片查看器仍按原始媒体顺序打开

不采用“按图片比例动态切换上下/左右布局”，因为这会破坏列表中的稳定统一。

## 一、布局规则

### 1.1 数量分支

`PhotoGrid` 保持按图片数量分支：

| 张数 | 布局 |
|------|------|
| 1 | 维持现有单图布局 |
| 2 | 新增主辅拼贴布局 |
| 3 | 维持现有一行三格 |
| 4–9 | 维持现有 3 列网格 + overflow |

也就是说，本次只替换 `2 张图` 的布局，不影响 1 张、3 张和 4 张以上的规则。

### 1.2 双图主辅比例

双图布局使用固定高度和固定主辅比例：

```ts
const PRIMARY_RATIO = 0.64;
const SECONDARY_RATIO = 0.36;
```

在容器总宽度扣除 gap 后：

```ts
const primaryWidth = (containerWidth - GAP) * PRIMARY_RATIO;
const secondaryWidth = containerWidth - GAP - primaryWidth;
const collageHeight = maxPhotoHeight;
```

外层为横向排列，不根据图片原始方向切换成纵向堆叠。

### 1.3 圆角与容器

- 双图整体仍处于同一张卡片内容区域内
- 主图位应用左侧圆角
- 辅图位应用右侧圆角
- 两张图共享相同高度
- 若卡片底部仍有 caption / meta，沿用现有卡片对图片区的圆角裁切逻辑

目标是让双图在视觉上像一个整体，而不是两张独立的小方块。

## 二、主图排序规则

### 2.1 默认顺序

默认保留用户顺序：

```ts
displayOrder = [0, 1];
```

也就是第一张图默认进入主图位，第二张图默认进入辅图位。

### 2.2 交换条件

只有当第二张图“明显更适合”主图位时才交换，避免系统频繁改动顺序造成心智混乱。

建议只使用轻量、可解释的规则，不引入复杂视觉打分：

1. 读取每张图的 `metadata.aspectRatio`
2. 计算它放入主图位时，与主图位目标比例的偏差
3. 如果第二张的偏差显著小于第一张，且差值超过阈值，则交换

示意：

```ts
const PRIMARY_TARGET_ASPECT = primaryWidth / collageHeight;
const SWAP_THRESHOLD = 0.18;
```

```ts
const lossA = Math.abs(normalizedAspect(photoA) - PRIMARY_TARGET_ASPECT);
const lossB = Math.abs(normalizedAspect(photoB) - PRIMARY_TARGET_ASPECT);

if (lossA - lossB > SWAP_THRESHOLD) {
  displayOrder = [1, 0];
}
```

这里的阈值必须保守，宁可少交换，也不要让用户觉得“系统经常把第二张提成主图”。

### 2.3 无元数据兜底

若任意图片缺少 `metadata.aspectRatio`：

- 不进行智能交换
- 直接保留原始顺序 `[0, 1]`

这样逻辑最稳定，也避免为历史数据或异常媒体引入不确定行为。

---

## 三、数据流与交互

### 3.1 展示顺序与原始顺序分离

双图布局需要区分：

- `originalIndex`：用户原始媒体顺序
- `displayIndex`：当前主辅布局的显示顺序

如果发生交换：

```ts
displayOrder = [1, 0];
```

则显示上第二张可能出现在左侧主图位，但点击事件仍需映射回原始索引：

```ts
onPhotoPress?.(displayOrder[displayIndex]);
```

### 3.2 查看器行为

无论布局是否交换：

- 点击视觉上的主图，打开其对应的原始图片索引
- 点击视觉上的辅图，打开其对应的原始图片索引
- 查看器内部仍按原始 `entry.media` 顺序左右浏览

这样既允许展示层优化版式，又不改变用户对图片顺序的理解。

---

## 四、错误处理

### 4.1 单图失败不回退布局

若双图中的任意一张图片加载失败：

- 保留当前双图主辅拼贴布局
- 在对应位置显示缺图占位
- 不回退成单列、方格或其他布局

原因是本次的最高优先级是“稳定统一”，失败态也必须维持同样的版式骨架。

### 4.2 缺图占位规则

- 主图失败：显示主图位大小的占位块
- 辅图失败：显示辅图位大小的占位块
- 占位块继承各自的尺寸和圆角

这样失败态不会造成卡片高度塌陷、左右错位或边角不一致。

---

## 五、组件边界

不建议把双图排序和尺寸计算塞回 `EntryCard`。

推荐保持现有边界：

- `EntryCardDefaultContent.tsx`：只负责把 `photos`、`maxPhotoHeight`、`onPhotoPress` 传给 `PhotoGrid`
- `PhotoGrid.tsx`：按图片数量选择单图、双图拼贴、多图网格
- `usePhotoGridController.ts`：负责容器宽度、2 张图的显示顺序、点击索引映射、overflow
- `PhotoGridCells.tsx`：负责主图位 / 辅图位的具体渲染

这样后续如果继续调双图布局，只会落在 `photo-grid` 范围内，不会影响 `EntryCard` 的其他职责。

## 六、测试要求

重点验证规则，不只验证静态样式。

| 场景 | 预期行为 |
|------|---------|
| 1 张图 | 继续使用现有单图布局 |
| 2 张图 | 不再渲染 2 列方格，而是渲染主辅拼贴 |
| 双图默认顺序 | 第一张默认主图，第二张默认辅图 |
| 第二张明显更适合主图 | 触发交换，显示顺序变为 `[1, 0]` |
| 差值未超过阈值 | 不交换，保持原始顺序 |
| 缺少 aspectRatio | 不交换，保持原始顺序 |
| 点击主图/辅图 | 能正确映射回原始图片索引 |
| 主图加载失败 | 保留主图位占位，不破坏整体布局 |
| 辅图加载失败 | 保留辅图位占位，不破坏整体布局 |
| 3 张图 | 继续使用现有 3 列逻辑，无回归 |
| 4 张以上 | 继续使用现有网格与 overflow，无回归 |

---

## 七、不做的事

本次明确不做以下内容：

- 不根据横图/竖图在左右拼贴与上下拼贴之间动态切换
- 不引入复杂的 AI 审美排序或内容识别
- 不修改图片查看器的数据结构或翻页顺序
- 不调整 3 张图及以上的布局规则

这些方案虽然更“聪明”，但都会削弱当前最重要的稳定统一目标。

---

## 结论

双图卡片采用 `固定高度 + 横向 64/36 主辅拼贴`，是当前约束下最成熟、最稳妥的方案：

- 比对称双栏更能吸收随机比例
- 比错位杂志排版更适合时间轴连续浏览
- 保留“第一张优先”的顺序语义
- 只在明显更合适时做保守交换

该方案能在不动数据模型、不扰动其他图片数量规则的前提下，集中优化 2 张图卡片的观感与一致性。
