# App 前后端交互与同步流程 Draw.io 设计

## 目标

生成一份可直接导入 draw.io / diagrams.net 的 `.drawio` 文件，用于梳理当前 MemoryCapsule App 的前后端交互顺序、用户操作流程、自动同步流程和异常分支。

## 输出结构

文件路径：

- `docs/diagrams/app-frontend-backend-sync.drawio`

采用单文件多页结构，拆分为 3 个 page：

1. `总览`
   - 展示用户层、前端本地层、同步/上传层、后端接口层的整体关系
   - 明确主链路是 `/api/sync` + `/api/media/upload` + `/api/entries`
   - 标注旧备份接口 `/api/sync/upload|download|status` 不是首页主链路

2. `用户操作流程`
   - 文字新增
   - 照片新增
   - 语音录制与上传
   - 编辑、删除、播放/查看
   - 搜索、筛选
   - 登录、注册、开启云模式、首次同步决策、手动同步、退出登录
   - 切换后端地址
   - 备份导出、备份导入

3. `系统自动同步与异常`
   - 冷启动恢复
   - 回到前台
   - 网络恢复
   - 自动补传照片/语音
   - 增量同步请求与后端事务处理
   - 冲突副本生成
   - 上传失败 / 同步失败 / 云模式切换中断

## 设计原则

- 以代码实际实现为准，不补充未落地的理想流程
- 优先保证可读性，避免单页巨图
- 节点名称面向产品和研发都可理解，必要时在节点内点明关键接口名
- 使用颜色区分角色：
  - 用户操作：绿色
  - 前端 UI / Store：蓝色
  - 本地数据层：紫色
  - 上传/同步服务：橙色
  - 后端接口/服务：青色
  - 异常/风险：红色

## 已覆盖的关键事实

- 本地 SQLite 是事实源，前端优先落本地再异步推云
- 文字记录直接走 `/api/sync`
- 照片记录先走 `/api/media/upload`，再走 `/api/sync`
- 语音记录先走 `/api/media/upload`，再直接走 `/api/entries`
- 云端更新冲突依赖 `baseUpdatedAt` 比较，冲突后生成本地冲突副本
- 网络恢复时当前只补跑媒体上传队列，不主动触发纯文字 `syncNow()`
