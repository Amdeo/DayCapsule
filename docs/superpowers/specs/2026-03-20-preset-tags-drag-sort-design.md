# 预制标签拖拽排序设计文档

**创建日期**: 2026-03-20
**状态**: 已实现
**版本**: 1.0

---

## 背景

当前预制标签管理页已经支持：

- 查看当前预制标签
- 新增预制标签
- 删除预制标签
- 恢复初始预制标签

但还不支持调整标签顺序。对于会出现在快速选择区域中的预制标签来说，顺序本身是重要信息：

- 用户希望把更常用的标签排在前面
- 当前只能通过删除再重建的方式间接调整顺序，成本过高
- 页面既然已经是“当前预制标签”的唯一管理入口，就应支持直接编排这组标签顺序

因此，需要在预制标签管理页中增加长按拖拽排序能力。

---

## 目标

- 预制标签管理页支持长按拖拽排序
- 拖拽后的顺序立即持久化
- 编辑器和搜索页后续读取到新的标签顺序
- 保持现有新增、删除、恢复能力不变

---

## 最终方案

### 1. 直接对当前预制标签列表做拖拽排序

拖拽排序只作用于当前这一组预制标签，不新增第二套列表，也不引入“临时显示顺序”概念。

也就是说：

- 用户拖动的就是当前预制标签本身
- 排序结果会写回 store
- 排序结果会持久化保存

### 2. 交互采用“长按整行拖拽”

标签管理页中的每个标签项支持：

- 长按进入拖拽
- 拖动到目标位置
- 松手完成排序

本次不引入额外“排序模式”，也不单独增加拖拽手柄。

### 3. 拖拽时提供最小必要反馈

为了让用户明确自己正在排序，拖拽过程中提供轻量视觉反馈：

- 被拖拽项高亮或浮起
- 其他项让位

但本次不做额外复杂动画设计，不扩展为完整的编辑器式排序体验。

### 4. 现有行为保持不变

除排序能力外，其他规则保持现状：

- 新增标签仍追加到尾部
- 删除标签逻辑不变
- 恢复初始预制标签后恢复为默认顺序
- 设置入口和页面其他结构不变

## 不在范围内

- 不新增排序模式按钮
- 不增加上移/下移按钮
- 不加拖拽手柄
- 不改设置页和侧边栏入口
- 不改编辑器或搜索页 UI
- 不重构标签数据模型

---

## 验收标准

- 标签管理页支持长按拖拽排序
- 排序完成后顺序立即更新
- 排序结果被持久化保存
- 新增标签仍追加到列表尾部
- 恢复初始预制标签后顺序恢复默认模板顺序
- 删除能力保持可用
- 相关测试覆盖排序与持久化行为并通过

---

## 回归风险

### 1. 删除与拖拽手势冲突

右侧删除按钮必须继续独立可用，不能因为整行支持长按拖拽而误触或失效。

### 2. 排序只改视图未改数据

如果页面中顺序变了，但重新进入后恢复旧顺序，说明排序没有写回 store 或没有持久化。

### 3. 恢复默认与新增逻辑被破坏

排序能力不应影响：

- 新增标签默认插入尾部
- 恢复默认恢复默认顺序
- 删除后剩余顺序保持稳定

### 4. 测试过度耦合手势细节

拖拽测试应重点覆盖排序结果和持久化，不应过度依赖复杂动画或具体手势实现细节，否则会导致测试脆弱。
